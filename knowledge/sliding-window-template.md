# 滑动窗口核心模板

> 来源：Blind 75 专题精讲

## 核心模板（万能框架）

```java
int left = 0, right = 0;
while (right < s.length()) {
    // 1. 扩大窗口：right 指向的元素加入窗口
    char c = s.charAt(right);
    // ... 更新窗口数据 ...

    // 2. 收缩窗口：当窗口不满足条件时
    while (/* 窗口不合法 */) {
        char d = s.charAt(left);
        // ... 更新窗口数据 ...
        left++;         // 左指针右移
    }

    // 3. 更新答案
    // ... 记录最长/最短 ...
    right++;            // 右指针右移
}
```

## 两字真言

| 场景 | 右指针 | 左指针 |
|------|--------|--------|
| **找最长**（如 3） | 窗口合法时继续走 | 窗口非法时跟上 |
| **找最短**（如 76） | 窗口不满足时拼命走 | 窗口满足时试探收缩 |

## 自查清单

- [ ] 右指针 `r`：每一轮循环只增加一次
- [ ] 左指针 `l`：条件不满足时用 `while` 收缩
- [ ] 操作顺序：先操作 map/数据，再移动指针
- [ ] 长度计算：统一用 `r - l + 1`，不要额外计数变量
- [ ] Java Integer 比较：永远用 `.equals()` 而不是 `==`
- [ ] 初始化：求最小值 → `Integer.MAX_VALUE`；求最大值 → `0`

## Minimum Window Substring 关键设计

### valid 计数器原理
- `need[]`：目标字符串 t 每种字符的需求
- `window[]`：当前窗口计数
- `valid`：记录**有多少种字符**已经满足了 need 的要求
- `totalNeeded`：t 中不同字符的种类数
- 当 `valid == totalNeeded` 时，窗口已覆盖 t

### 为什么不用全量对比？
每次移动都遍历 need[128] 比较 → O(K×N)。用 valid 变量在 `window[c] == need[c]` 瞬间 +1 → O(1)。

### 只用 HashMap 的替代方案（减法计数法）

```java
int[] map = new int[128];     // 存 t 的需求量
int count = t.length();       // 还差多少个字符

// 遇到需要的字符（map[c] > 0）→ count--
// 踢走必需的字符（map[c] > 0 后）→ count++
```

此方案虽简洁，但面试推荐 valid 方案：通用性强、可读性高、不容易写错正负号。

## Java 避坑

- **Integer 缓存**：-128 到 127 之外的 Integer，`==` 比较的是地址，必须用 `.equals()`
- **窗口收缩顺序**：**先 remove/更新，再移动 l**，顺序颠倒会导致移除错误字符
