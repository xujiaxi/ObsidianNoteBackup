# BFS / DFS 核心要点

> 来源：Blind 75 专题精讲（Number of Islands + Clone Graph）

## 什么时候用什么

| 场景 | 推荐 | 原因 |
|------|------|------|
| 连通分量计数 | DFS | 代码简洁，递归直观 |
| 最短路径 | BFS | 天然逐层搜索，第一次到达即最短 |
| 拓扑排序 | BFS (Kahn) | 入度表 + Queue |
| 环检测 | DFS | 三色标记法 |
| 遍历所有路径 | DFS | 回溯法本质就是 DFS |

## DFS vs BFS 内存对比

| 维度 | DFS (递归) | BFS (迭代) |
|------|-----------|-----------|
| 内存位置 | 系统调用栈 (Stack) | 堆内存队列 (Heap) |
| 主要开销 | 递归深度（函数栈帧） | 队列宽度（每层节点数） |
| 风险 | 大数据 → StackOverflow | 大数据 → OutOfMemory |
| 代码量 | 极简 | 较长，需要 Queue + visited |

## 堆 vs 栈（面试必问）

```
Heap (堆): 存放数组/图的数据实体（只有一份）
Stack (栈): 存放函数的"分身"（每个递归调用一个栈帧）

每个栈帧只记录：
  - 当前坐标 / 节点引用
  - 返回地址

结论：撑爆内存的是"函数分身的数量"，不是"数据本身的大小"
```

## 关键设计模式

### 1. 淹没策略（Sinking / In-place Modification）
直接修改输入数据作为 visited 标记，省额外空间。
```java
grid[r][c] = '0';  // 标记已访问
```
⚠️ 面试时需确认是否允许修改原数据

### 2. 哈希表防环（Graph Clone）
```java
visited.put(node, cloneNode);  // 先入表，再递归！
```
交换顺序 → A→B→A 环：死循环 StackOverflow

### 3. 矩阵 vs 图对比
| 维度 | 矩阵题（如岛屿） | 图题（如克隆图） |
|------|---------------|----------------|
| 邻居定义 | `r+1, c` 等坐标运算 | `node.neighbors` 列表 |
| 越界风险 | 坐标可能出界 | 无越界，只有 null |
| 检查条件 | `r < 0 || r >= rows` | `node == null` |
| 数据结构 | 二维数组 | Node + neighbors List |
